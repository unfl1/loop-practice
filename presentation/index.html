Loop Engineering

한 번 잘 시키는 것에서,
결과가 다음 실행을 바꾸는 구조로

Expansion Map

Prompt → Context → Harness → Loop

공식적인 역사나 우열이 아니라, AI에게 맡기는 범위를 넓힐 때 추가되는 설계 관점입니다.

왜 관점이 넓어지는가

좋은 지시는 방향을 정하지만 판단에 필요한 정보까지 채우지는 못합니다. 정보를 충분히 줘도 실제 파일과 도구에 접근하지 못하면 행동할 수 없고, 행동이 가능해도 결과를 평가해 다시 시도하는 구조는 별도로 설계해야 합니다.

네 관점이 맡는 역할

Prompt는 행동 방향을, Context는 판단 재료를, Harness는 실행과 관찰이 가능한 공간을 제공합니다. Loop는 실행 결과 이후 무엇을 평가하고 기억하며 다음 입력을 어떻게 바꿀지 결정합니다.

01 · Prompt

어떻게 지시할까?

역할, 목표, 제약과 출력 형식을 설계해 해야 할 일을 분명하게 만듭니다.

없는 정보까지 제공하지는 못합니다.
02 · Context

무엇을 보여줄까?

문서, 대화, 코드와 현재 상태처럼 판단에 필요한 정보를 제공합니다.

정보만으로 실제 행동할 수는 없습니다.
03 · Harness

어디서 일하게 할까?

파일, Git, 테스트, 로그와 권한을 연결해 작업과 관찰을 가능하게 합니다.

한 번의 행동이 자동 개선을 뜻하지는 않습니다.
04 · Loop

무엇을 다시 하게 할까?

평가와 피드백을 다음 입력에 반영해 반복이 개선을 만들게 합니다.

평가가 다음 실행을 실제로 바꿉니다.
Prompt는 방향, Context는 판단 재료, Harness는 행동 공간, Loop는 결과 이후의 다음 행동을 설계합니다.

Prompt Engineering

AI에게 어떻게 잘 시킬 것인가?

핵심 질문 · “AI에게 무엇을, 어떤 조건으로 수행하라고 말할 것인가?”

무엇인가

Prompt Engineering은 AI가 원하는 방향으로 응답하도록 지시문의 구조와 표현을 설계하는 접근입니다. 역할, 목표, 배경, 제약조건, 출력 형식과 예시를 조합해 해야 할 일을 명확하게 만듭니다.

왜 필요한가

지시가 모호하면 같은 모델도 서로 다른 결과를 냅니다. 좋은 Prompt는 성공 기준과 작업 경계를 선명하게 해 불필요한 추측을 줄이고 결과의 일관성을 높입니다.

Context Engineering

AI가 판단할 때 무엇을 보여줄 것인가?

핵심 질문 · “이 판단을 정확히 하려면 지금 어떤 정보를 함께 제공해야 하는가?”

Prompt와의 차이

Prompt는 AI에게 무엇을 하라고 말하는 지시입니다. Context는 그 지시를 수행할 때 참고하는 사용자 요구, 이전 대화, 문서, 코드, 검색 결과, 메모리와 현재 상태입니다.

해결하는 문제

Context가 빠지면 기존 요구를 놓치거나 잘못된 가정을 하고 현재 프로젝트와 맞지 않는 답을 만들 수 있습니다. 같은 Prompt도 무엇을 함께 보여주느냐에 따라 판단 품질이 달라집니다.

AI

관점은 “어떻게 말할까?”에서 “무엇을 알고 판단하게 할까?”로 넓어집니다. 그러나 충분히 알아도 행동할 환경이 없다면 작업 범위는 제한됩니다.

Harness Engineering

AI가 어떤 환경에서 실제로 일하게 할 것인가?

핵심 질문 · “AI에게 어떤 도구, 관찰 수단과 권한을 가진 작업 환경을 줄 것인가?”

답변에서 행동으로

Harness Engineering은 AI가 텍스트를 생성하는 데서 끝나지 않고 실제 작업을 수행하고 그 결과를 관찰하도록 주변 실행 환경을 설계하는 것입니다. Prompt와 Context를 현실의 행동으로 연결합니다.

검증 가능한 작업

파일 저장, 테스트 실행, 브라우저 확인, 로그 분석과 버전 관리를 연결하면 실행 결과를 근거로 다음 결정을 내릴 수 있습니다. 권한은 가능한 행동의 범위와 안전 경계를 정합니다.

Loop Engineering

평가 결과가 다음 실행을 바꾸게 하려면?

Harness vs Loop

작업 환경과 반복 구조는 다른 질문에 답합니다

Harness Engineering

AI가 사용할 도구, 파일 접근, 테스트, 로그, 실행 환경과 권한을 설계합니다. 핵심 질문은 “AI에게 어떤 작업 환경을 줄 것인가?”입니다.

  • 무엇을 실행하고 관찰할 수 있는가?
  • 어떤 권한과 안전 경계를 가지는가?

Loop Engineering

결과 이후 평가, Feedback, 상태 유지, 종료 조건과 최고 결과 보존을 설계합니다. 핵심 질문은 “결과 이후 무엇을 다시 하게 할 것인가?”입니다.

  • 무엇을 다음 실행에 전달하는가?
  • 언제 멈추고 무엇을 기억하는가?

Loop를 반복하면 실제로 목표에 더 가까워질까?

왜 이 실험인가

실제 포메라니안 사진을 고정 원본으로 두고 첫 결과는 일부러 단순한 손그림으로 제한합니다. 형태 차이가 분명해 평가와 피드백이 다음 결과를 어떻게 바꾸는지 관찰하기 좋습니다.

무엇을 검증하는가

이미지 모델의 절대 성능을 자랑하려는 것이 아닙니다. Evaluator가 찾은 구조적 차이를 Prompt Refiner가 다음 입력에 반영할 때 실제 결과가 어떻게 달라지는지 확인합니다.
